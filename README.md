# Clip-Copilot

一个以自然语言和直接操作共同驱动的 **AI 视频编辑器**。用户提供视频与目标，AI 帮助理解素材、组织内容和执行编辑；用户能预览、纠正、撤销，并继续精修。核心工作流不依赖付费剪辑软件。

**当前方向：先建立可运行、可纠正、可评测的剪辑 harness，再用真实任务研究怎样提高质量、减少人工修改。** 具体引擎与产品架构尚未确定。

## 产品目标

- 用户可以只提供一个视频和一句目标；脚本与提纲是可选信息。
- 新手能得到易检查的粗剪，熟练用户能精确控制和继续修改；分别验证两类需求。
- 产物包含可编辑工程，支持局部纠正、保存、恢复与导出。
- AI 结合转写、声音和按需查看的画面理解素材，保留编辑依据与源片段映射。
- 以成片质量和达到可接受结果的总时间衡量收益，包括人工纠正与运行成本。

首个候选实验是单人讲话类视频的粗剪整理，例如口播、讲解和带演示的录制。它是验证闭环的起点，尚不代表最终用户定位。静默动作、强调性重复和必要停顿也需要保留，不能只按字幕或静音机械剪切。

## Harness 的作用

Harness 是 agent 的运行与评测环境：提供素材索引、可编辑工程、受约束的编辑工具、预览检查、人工纠正与恢复，以及可复现的实验记录。

计划中的首个闭环是：

> 视频＋目标 → 可编辑粗剪 → 预览与局部纠正 → 保存、恢复与导出 → 回放并比较实验。

在同一批任务和可比预算下，逐步比较规则基线、转写辅助、按需视听查询和预览后修订，判断哪些方法确实有帮助。这一闭环是后续建设目标，当前仓库尚未完整实现。

## 当前仓库

这是探索中的历史原型，目前包含：

- 工作区状态、素材登记、审阅、检查点与恢复。
- Electron/React 工作台与 AI 工具调用、操作确认。
- Kdenlive/LMMS 模板工程生成、媒体与渲染验证。
- 编辑器适配接口与相关测试；开发分支另有 Resolve 外部桥接探索。

这些能力可作为后续实验参考，也可以重构或替换。当前工作台尚不能视为独立时间线编辑器；模板工程生成也不等于任意素材的通用剪辑。

此前的 Resolve-first 路线已撤回。官方将外部脚本控制列为 Studio 能力，旧代码中的 Free 兼容性假设需要后续纠正，不能作为当前接入承诺。Kdenlive 和 Shotcut 等开源项目是技术与工作流参考，产品目标是在 Clip-Copilot 内完成主要操作。

## 开发与验证

现有代码使用 TypeScript、Node.js ≥ 24、Electron 和 React。下面是已有脚本；不是新方向的验收清单。

在依赖已经准备好的环境中，可按需进行定向检查：

```bash
npm run check           # 主项目 TypeScript 检查
npm run check:renderer  # GUI 渲染层 TypeScript 检查
npm run test:editor     # 现有编辑器协议及相关回归测试
```

这些检查通过也不能证明新的剪辑闭环已经完成。旧媒体流程还可能需要 FFmpeg、Kdenlive/LMMS 及环境配置，不能直接把它作为新产品的安装流程。

```bash
npm test  # 构建及完整旧回归，包含实际媒体/原生流程
npm run gui  # 构建并启动现有工作台
```

重型构建、完整测试、GUI 演练和大数据处理优先使用云端免费资源。调用具体服务前需告知用途、权限和上传内容并获得授权；确需本机兜底时遵守仓库的资源规则。[现有 CI](.github/workflows/ci.yml) 包含历史流程，后续应按新方向调整，不能直接作为新产品验收依据。
